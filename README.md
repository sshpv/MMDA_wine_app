# 🍷 Сомелье на логистической регрессии

Streamlit-приложение к ДЗ-3: по лабораторному анализу вина модель оценивает вероятность того,
что вино «хорошее» (оценка экспертов ≥ 7), и решает, включать ли его в подборку.

## Запуск

Python **3.13** (проверено на 3.13).

```bash
cd wine_app
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется http://localhost:8501.

## Содержимое

| Файл | Что это |
|---|---|
| `app.py` | приложение (модель внутри не обучается) |
| `model.joblib` | пайплайн `StandardScaler` + `LogisticRegression`, обученный на train |
| `config.json` | порог по умолчанию — максимизирует F1 на валидации (≈ 0.269) |
| `test.csv` | тестовая выборка для вкладки метрик |
| `.streamlit/config.toml` | тема оформления |
| `images/` | мемы (необязательно; без них приложение работает) |

## Вкладки

1. **Оценка одного вина** — ввод 12 признаков, вероятность и решение при пороге из сайдбара.
2. **Модельные метрики** — матрица ошибок, precision / recall / F1, ROC- и PR-кривые с точкой текущего порога.
3. **Пакетное предсказание** — загрузка CSV, таблица с вероятностями и решениями, скачивание результата.
4. **Что выучила модель** — коэффициенты логистической регрессии.

## Кэширование (задание 4.5)

- **Модель** загружается через `st.cache_resource`: один общий объект на весь сервер,
  он отдаётся по ссылке без копирования. Модель мы только читаем, поэтому разделять её безопасно.
- **Таблицы** (`test.csv`) и **вероятности на тесте** кэшируются через `st.cache_data`.
  Результат сериализуется, и каждый вызов получает свою копию, так что случайная модификация
  таблицы не испортит кэш. Ключ кэша — хеш аргументов. У `test_proba(_model, X)` модель не хешируется
  (подчёркивание в имени аргумента). Вероятности считаются один раз, а при движении слайдера
  меняется только сравнение с порогом.
- **Без декоратора** `joblib.load` выполнялся бы при каждом действии пользователя, потому что Streamlit
  перезапускает скрипт сверху вниз. Это лишнее чтение с диска, задержки и копии модели в памяти.
  Через `cache_data` модель тоже грузить не стоит: её пришлось бы pickle-копировать при каждом обращении.
